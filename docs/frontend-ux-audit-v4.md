# Frontend UX Audit v4

For the docs hub and operator guides, start at [README.md](./README.md). This note is the `GBX-500` audit of the completed v3 SPA before v4 redesign work changes the operator console.

## Executive Summary

The v3 SPA has the right technical foundation and a useful breadth of operator data. It successfully exposes workspace health, action queues, selected-session snapshots, mutation controls, lineage, compare, runtime context, verification cues, metrics, and raw events from deterministic backend-derived data.

The product problem is hierarchy. The current interface renders almost every available surface at once, especially after selecting a session. Operators can eventually find evidence and actions, but the UI does not reliably answer the most important questions first: what needs attention, what action is safest, and which evidence matters right now.

The biggest concrete defects visible in the archive are mobile queue-table clipping, decorative inspector tabs, overlong selected-session stacks, mixed-priority action controls, noisy status semantics, buried compare and evidence surfaces, and artifact-drift copy/wrapping issues.

## Surface Audit

### Workspace Overview

The overview correctly starts in the console rather than a landing page. It shows workspace path, runtime state, queue counts, projection counts, and prioritized sessions from `GET /sessions/aggregate`.

Problems:

- the first screen treats workspace metrics, queues, and session rows as similarly weighted cards rather than a directed attention model
- the `Action` count is visible, but it does not clearly explain the highest-priority operator decision
- degraded projection count and runtime state are visible, but their relationship to session urgency is unclear
- the empty workspace is understandable but plain; it uses the same card-heavy scaffolding as busy states instead of a more intentional calm operational state

Preserve:

- direct, local-first overview entry at `/app`
- server-prioritized aggregate rows as the source of truth
- compact workspace identity and runtime summary

### Queues

The queue list covers approvals, questions, failures, degraded, active, historical, and all sessions. Counts are visible and stable.

Problems:

- desktop queue rows are generic table rows, so the session ID competes with the next action instead of supporting triage
- mobile queue rows keep desktop columns; `NEXT ACTION` text is clipped horizontally in all queue-heavy mobile states
- approvals, questions, failures, and degraded sessions do not have enough row-level differentiation for fast scanning
- historical sessions appear in the same information shape as urgent work

Preserve:

- backend queue membership semantics
- direct links into selected-session routes
- compact queue counts and current queue state

### Selected-Session Inspector

The inspector exposes a rich snapshot: status, stream posture, transcript, lineage, compare, actions, runtime context, verification, metrics, and event evidence.

Problems:

- the default selected-session view renders nearly every surface at once
- visible tabs do not meaningfully gate content, so they add chrome without reducing cognitive load
- desktop becomes a dense grid of equal-weight panels
- mobile becomes a very tall stack where the operator passes workspace summary, queues, table, selected metadata, tabs, actions, transcript, lineage, compare, runtime, verification, metrics, and events in one flow
- status chips, metadata, and secondary panels appear before the interface has established the selected session's story and next decision

Preserve:

- stable deep links for selected sessions and tabs
- raw evidence availability
- existing generated API contracts as the snapshot source

### Actions

The SPA can submit prompts, answer questions, approve, deny, and fork. The Playwright workflow proves the basic mutation path still works.

Problems:

- pending approvals and questions compete with the freeform composer and fork controls
- the primary action does not dominate the selected-session view even when the backend says action is required
- mobile users must scroll through generic session context before reaching the decisive action surface
- approval and question controls need stronger subject, risk, reason, pending, success, conflict, and recovery states near the action itself

Preserve:

- explicit approve and deny actions
- answer and prompt draft behavior
- snapshot/SSE refresh as canonical mutation feedback

### Transcript And Timeline

The transcript is present and live SSE updates appear in fixture-backed runs.

Problems:

- transcript messages are isolated from turn metrics, approvals, questions, tool calls, failures, and fork boundaries
- there is no strong narrative preview on the selected-session overview
- the current layout asks operators to piece together the session story from disconnected panels
- timeline behavior is underdeveloped relative to the amount of turn data exposed by snapshots

Preserve:

- raw transcript ordering
- live update rendering through the existing SSE path
- access to metrics and event evidence for deeper inspection

### Lineage And Compare

Lineage and compare data are reachable and deterministic fixtures cover parent/child and compare target states.

Problems:

- lineage appears as another panel rather than a navigation model anchored around the current session
- compare is too buried for branch triage and reads more like a count summary than a difference view
- mobile compare context sits far below unrelated overview content

Preserve:

- persisted lineage fields as the only source of branch relationships
- direct navigation into child and compared sessions
- route-state preservation for compare targets

### Runtime Context, Evidence, And Verification

The SPA exposes runtime context, repository context, working set, artifact summaries, projection health, metrics, and events.

Problems:

- diagnostics dominate the default inspector instead of sitting behind intentional evidence surfaces
- advisory artifact drift can visually compete with runtime failures or session failures
- artifact labels can run together, such as label text flowing directly into summary text
- long local paths and target paths wrap awkwardly on mobile
- evidence-heavy states can push the current action below secondary content

Preserve:

- raw event ordering and sequence numbers
- artifact-backed summaries and working-set provenance
- distinction between replay/eval evidence and browser-side execution; the SPA should not run replay or eval itself

### Mobile Behavior

Mobile is technically reachable and the console renders without the old dev overlay after `GBX-493`.

Problems:

- the session table horizontally clips important next-action text
- selected-session pages are too tall for focused intervention
- the mobile workflow is a squeezed desktop layout rather than a deliberate drill-in model
- actions, compare, and evidence are reachable but often too far down the page

Preserve:

- readable top-level workspace and queue stack
- direct selected-session deep links
- 390px viewport coverage in the screenshot archive

## Issue Inventory

### Workflow Blockers

- Mobile queue tables clip `NEXT ACTION` text, preventing operators from reading why a session needs attention.
- Inspector tabs do not gate actual content, so the selected-session view cannot support focused workflows.

### High-Friction Hierarchy Issues

- Pending approvals and questions do not consistently outrank freeform prompt and fork controls.
- Selected-session overview renders transcript, lineage, compare, actions, runtime, verification, metrics, and events together.
- Compare and evidence are available but not shaped around branch triage or the next operator decision.
- Runtime owner, stream posture, projection health, session status, queue urgency, and verification evidence have similar visual weight.

### Accessibility Problems

- Status and health meaning can depend too much on badge color and spatial position.
- The long selected-session stack makes keyboard order and focus recovery harder to reason about.
- Action feedback is not yet local enough to the action that caused it.

### Responsive Layout Problems

- Mobile tables preserve desktop columns instead of becoming stacked attention rows.
- Long artifact paths and evidence rows wrap poorly on mobile.
- Primary actions can fall below multiple secondary panels on narrow screens.

### Visual Polish Issues

- Busy and empty states use similar card scaffolding, flattening the emotional difference between calm and urgent states.
- Too many panels have equal border, heading, and badge treatment.
- Advisory verification cues can look as severe as runtime or session failures.

### Copy Issues

- Evidence labels and summaries can run together without enough separation.
- Queue and status copy identifies categories but does not always explain the operator's next decision.
- Historical and degraded states need clearer language that distinguishes inspectability, projection health, and runtime liveness.

## Already-Good Surfaces To Preserve

- The SPA is local-first and keeps backend snapshots, aggregate responses, SSE, and mutations as the source of truth.
- The FastAPI static-serving model and Next static export path remain appropriate.
- The route model supports `/app`, queue routes, selected-session deep links, query-string session selection, tab state, and compare targets.
- The current fixture-backed Playwright workflow covers browsing queues, opening sessions, receiving SSE updates, answering questions, resolving approvals, and forking.
- The screenshot archive now covers a useful matrix of representative desktop and mobile states.
- Raw transcript, runtime context, verification, metrics, event evidence, lineage, and compare data are already available; v4 should reorganize them rather than delete them.

## Redesign Implications

The audit supports the existing v4 build order:

- `GBX-501` should define a stricter interaction model for attention rail, narrative, action rail, evidence, and responsive drill-in behavior.
- `GBX-511` should replace the mobile-clipping table with dense attention rows.
- `GBX-520` and `GBX-521` should make tabs real and make overview content selective.
- `GBX-522` should promote urgent approvals and questions above generic composer and fork controls.
- `GBX-533`, `GBX-541`, and `GBX-542` should move diagnostics, compare, and verification into focused evidence surfaces with clearer copy and mobile wrapping.
